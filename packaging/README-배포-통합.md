# 기사작성기 — 배포 통합 가이드 (서버 + 클라이언트)

운영자 한 사람이 처음부터 끝까지 따라가는 순서로 쓴 문서다. 각 절은 요약만 하고 상세 절차는
서버·클라이언트 가이드(관련 문서, 10절)가 단일 출처다 — 두 문서와 서술이 다르면 그쪽이 맞다.

이 문서는 배포 폴더에 **동봉되지 않는다**(개발 리포 전용). 배포 폴더에는 각각
`README-배포.md`(서버)·`README-배포-클라이언트.md`(클라이언트)가 자동 동봉된다.

## 1. 전체 그림

```
서버 1대                              기자·데스크 PC N대
┌────────────────────────┐            ┌──────────────────┐
│ 기사작성기-server.exe  │  ←HTTP/SSE─│ 기사작성기.exe   │
│  ├─ web\  (화면 파일)  │            │ (Electron 접속형 │
│  └─ data\ (DB·업로드)  │            │  셸 — 데이터 0)  │
└────────────────────────┘            └──────────────────┘
```

- **화면(메뉴·편집기 등) 변경 = 서버만 재배포**하면 전 PC에 자동 전파된다.
- **셸(창·메뉴·서버 연결 방식) 변경 = 각 PC의 클라이언트 폴더 교체**가 필요하다.
- 클라이언트 PC에는 기사·계정 데이터가 저장되지 않는다(서버 주소 설정만 `%APPDATA%\기사작성기\config.json`).

## 2. 빌드 (개발 리포에서)

```bash
npm run dist:server   # → dist/기사작성기-server/  (서버 exe 약 90MB — Node 런타임 내장)
npm run dist:client   # → dist/기사작성기/         (클라이언트 폴더 약 348MB, 압축 약 140MB)
```

- 클라이언트 exe에는 아이콘과 버전(1.0.0)·제품명 PE 리소스가 빌드 시 자동 적용된다(서버 exe도 동일).
- 빌드 머신 요구사항·파이프라인 상세: 리포 `README.md`의 배포 절.

## 3. 서버 설치

상세: 서버 배포 폴더의 **`README-배포.md`** (1~12절). 요약:

1. `dist/기사작성기-server/` 폴더를 서버 머신의 쓰기 가능한 경로에 복사한다(`C:\Program Files` 금지).
2. **초기 계정**: 배포 폴더의 `data\`는 비어 있어 그대로는 로그인할 수 없다 — 개발 머신에서
   `npm run seed`로 만든(또는 기존 운영 중인) `news.db`를 `data\`에 복사한다(가이드 4절).
   시드 DB를 쓴 경우 로그인 후 **샘플 계정 비밀번호를 즉시 변경**한다(관리자 화면 → 사용자 관리).
3. LAN 개방 시 bat에서 `HOST`(예: `0.0.0.0`)와 `PORT`를 설정하고, Windows 방화벽 인바운드를 허용한다.
   `NODE_ENV=production`은 **금지**다(평문 HTTP에서 로그인이 조용히 실패한다 — 가이드 5절).
4. 수집을 쓰면 `COLLECTION_TOKEN`을 설정한다 — LAN 개방 상태에서 토큰이 없으면 수집 HTTP 라우트가
   503으로 닫힌다(정상 동작). 배부를 쓰면 `DIST_SPOOL_DIR` 설정 + 엠바고 시점 배부는 앱 내 타이머가
   없으므로 외부 스케줄러가 `POST /api/distribution/tick`을 주기 호출한다(가이드 6~7절).
5. `기사작성기-server.bat`으로 기동하고 브라우저에서 `http://<서버IP>:<PORT>/api/health`가
   `{"ok":true}`인지 확인한다.

## 4. 클라이언트 배포

상세: 클라이언트 배포 폴더의 **`README-배포-클라이언트.md`** (1~10절). 요약 — PC 1대당:

1. `dist/기사작성기/` 폴더를 대상 PC 로컬 디스크에 복사한다(무설치·관리자 권한 불요).
2. `기사작성기.exe` 실행 → 서버 주소 입력(예: `192.168.0.10:3001`) → [연결 확인] → [저장하고 시작].
3. **프로그램을 종료하고 다시 실행한다.** LAN 주소를 처음 저장한 그 실행에서는 복사·붙여넣기
   완화가 아직 적용돼 있지 않다(5절) — 이 재시작은 예외 상황이 아니라 **기본 설치 절차의 한 단계**다.
4. 로그인해 목록 상단 표시가 **'실시간'**인지 확인한다.

**대량 배포(권장)**: 각 PC 사용자의 `%APPDATA%\기사작성기\config.json`에
`{"schemaVersion":1,"serverUrl":"http://<서버IP>:<PORT>"}`를 미리 배치하면 2~3단계가 통째로
사라진다 — 첫 실행 시점에 이미 주소가 있어 부팅과 동시에 클립보드 완화까지 적용된다(5절).
설정은 **PC 사용자마다 따로**라는 점에 주의(폴더 복사로는 따라가지 않는다).

## 5. 클립보드 (중요)

평문 HTTP + LAN IP 주소에서도 **클라이언트 EXE는 복사·붙여넣기가 동작한다.** 셸이 부팅할 때
저장된 서버 출처 **하나만** secure context로 취급하는 Chromium 스위치를 적용하기 때문이다
(http + 비-loopback 주소일 때만 적용 — `127.0.0.1`·https 주소에는 적용 자체가 없다).

- **적용 시점은 "프로그램이 켜질 때 1회"다.** 그래서:
  - **최초 설정 직후에도 재시작 1회가 필요하다.** 주소를 처음 저장한 실행에서는 아직 완화가 없다
    — 재시작 안내 창이 뜬다. 신규 배포 PC는 예외 없이 한 번 껐다 켜야 한다(4절 3단계).
  - **서버 주소를 바꿀 때도** 같은 이유로 재시작이 필요하다(안내 창이 뜬다).
  - **config.json을 사전 배치하면 이 재시작 단계가 사라진다**(4절 대량 배포 — 권장 경로).
- **브라우저로 접속하면 같은 조건에서 여전히 막힌다**(브라우저에는 이 완화가 없다 — 목록 본문복사·
  에디터 붙여넣기 불가). 근본 해결은 서버 HTTPS 종단이며, HTTPS가 되면 이 스위치는 조건상
  자동으로 적용되지 않게 된다.

## 6. 알려진 제약

- **코드 서명 없음** — 처음 실행 시 SmartScreen·백신 경고가 뜰 수 있다(8절 표 참조).
- **자동 업데이트 없음** — 셸 변경은 폴더 교체, 화면 변경은 서버 재배포(1절 구분).
- **맞춤법 밑줄(빨간 줄) 없음** — 외부 통신(사전 다운로드)을 만들지 않기 위한 **확정 예외**다.
  맞춤법 검사는 에디터 메뉴의 맞춤법 기능을 쓴다.
- **새로고침은 메뉴(`보기 > 새로고침`) 또는 Ctrl+R** — **F5는 동작하지 않는 것이 현재 사양**이다.
- 폴더 크기: 클라이언트 약 348MB(압축 약 140MB), 서버 약 90MB + 화면 파일.

## 7. 운영

- **백업 = 서버 중지 후 `data\` 폴더 복사**(DB·업로드·스풀 전부 포함). **DB 파일 삭제 금지** —
  문제 대응은 삭제가 아니라 백업 복구다(서버 가이드 8절).
- **서버 업그레이드**: 새 폴더 배치 → 이전 `data\` 이동 → 기동(마이그레이션 자동·멱등).
  이전 폴더는 확인 전까지 보존한다(롤백 경로 — 서버 가이드 9절).
- **클라이언트 업그레이드**: 폴더 통째 교체(설정은 `%APPDATA%`에 있어 유지된다 — 클라이언트 가이드 8절).

## 8. 문제 해결

| 증상 | 원인 | 조치 |
|------|------|------|
| 클라이언트가 서버를 못 찾음 | 서버 미기동·주소/포트 오류·방화벽 | 오류 화면 안내 확인 → 주소 재확인 → [다시 연결] → 서버 담당자 확인(클라이언트 가이드 6절) |
| 로그인 후 실시간 표시가 '연결 끊김' | 실시간(SSE) 연결 끊김 | 잠시 대기(자동 재연결) → `보기 > 새로고침` → 계속되면 서버·네트워크 확인 |
| 복사·붙여넣기 안 됨 | 최초 설정·주소 변경 후 **재시작 전** 상태(5절) | 프로그램 종료 후 재실행. 그래도 안 되면 접속 주소가 저장된 주소와 같은지 확인 |
| 기사가 편집 잠금 상태로 남음 | 강제 종료·PC 다운으로 잠금 잔류 | 데스크(D)/관리자(Z)가 목록 우클릭 **Lock해제**로 푼다. **DB 직접 수정 금지** |
| SmartScreen 경고 | 서명되지 않은 실행 파일 | "추가 정보 → 실행"으로 진행. 회사 배포 시 보안 담당자에게 예외 등록 요청 |
| 방화벽으로 LAN 접속 불가 | 서버 PC 인바운드 차단 | 서버 exe(또는 해당 포트)의 Windows 방화벽 인바운드 규칙 허용(관리자 권한, 서버 가이드 11절) |
| 서버 콘솔에 "이미 실행 중" 후 즉시 종료 | 같은 데이터 폴더로 두 번째 서버 기동 | 기존 서버 종료 후 재시작 또는 `DATA_DIR` 분리(서버 가이드 11절) |

## 9. 검증 커맨드 (개발 리포에서)

```bash
npm run dist:server && npm run dist:client   # 검증 대상 산출물 빌드
npm run verify:integration                   # = node scripts/verify-integration.mjs --scenario all
```

서버 exe(임시 데이터 폴더)와 클라이언트 exe를 함께 띄워 실제 업무 루프를 자동 판정한다:
로그인 → 기사 작성 → 목록 실시간 반영 → 상세보기 팝업(720×800) → 송고 → 목록 이탈 +
loopback·LAN 두 시나리오의 secure context/클립보드 표면. 실행 중 720×800 팝업이 잠깐 화면에
뜨는 것이 정상이며, 실 데이터(리포 DB·사용자 설정)에는 절대 접근하지 않는다.
LAN 시나리오가 종료 코드 2로 끝나면 제품 결함이 아니라 방화벽 인바운드 차단이다(출력의
netsh 안내를 따라 허용 후 재실행). 창을 띄워 눈으로 보며 돌리려면 `--show`를 붙인다.
출력에 `unverified`(팝업 크기 미검증 — 비표시 모드의 렌더 스로틀)가 보이면 `--show`로
1회 재실행한다 — 그 실행이 팝업 720×800 검증의 소유자다.
