# 기사작성기 서버 — 배포 폴더 운영 가이드

이 문서는 배포 폴더에 동봉되는 운영 가이드다. 이 폴더만으로 서버를 설치·기동·백업할 수 있다.
서버·클라이언트를 아우르는 전체 설치 순서는 개발 리포의 `packaging/README-배포-통합.md`를 보라(배포 폴더 미동봉).

## 1. 구성

```
기사작성기-server\
├─ 기사작성기-server.exe    ← 서버 본체 (Node 런타임 + 서버 코드 + 의존성 전부 내장)
├─ 기사작성기-server.bat    ← 시작 스크립트 (환경변수 설정 예시 포함 — 권장 실행 방법)
├─ web\                     ← 웹 화면 파일 (exe가 같은 주소에서 서빙)
├─ data\                    ← 데이터 폴더 (news.db · uploads\ · rcv-spool\ · dist-spool\)
└─ README-배포.md           ← 이 문서
```

- **서버 머신에 Node 설치가 필요 없다.** 실행 파일 하나에 전부 들어 있다.
- **포터블이다** — 이 폴더를 통째로 복사하면 이동/백업이 끝난다. 데이터는 전부 `data\` 아래에 생긴다.

## 2. 요구사항

- Windows x64.
- 내장 Node 버전: **v24.16.0** (빌드 머신의 런타임이 그대로 실행 파일에 들어간다).
  Node를 올리려면 이 exe를 **재빌드**해야 한다(개발 리포에서 `npm run dist:server`).

## 3. 시작 / 중지

- 시작(권장): `기사작성기-server.bat` 더블클릭. (exe 직접 실행도 가능하지만 bat이 포트 설정과
  오류 메시지 확인(pause)을 제공한다.)
- 중지: 콘솔 창에서 `Ctrl+C` 또는 창 닫기.
- 접속 주소: `http://127.0.0.1:3001/login.do` (기본). LAN 개방 시 `http://<서버IP>:<PORT>/login.do`.

## 4. 최초 설치: 사용자 계정 준비

배포 폴더의 `data\`는 비어 있고 **사용자가 0명이라 그대로는 로그인할 수 없다.**
exe에는 계정 생성 경로가 없다(의도된 범위 결정 — 초기 계정 기능은 별도 확정 대상이다).

- (권장) 기존 운영 중인 `news.db`가 있으면: 서버를 멈추고 그 파일(과 `-wal`/`-journal` 동반 파일이
  있으면 함께)을 이 폴더의 `data\`에 복사한다.
- 신규 설치: 개발 머신(리포 + Node)에서 `npm run seed`로 만든 `news.db`를 `data\`에 복사하고,
  로그인 후 **샘플 계정 비밀번호를 즉시 변경**한다(관리자 화면 → 사용자 관리).

## 5. 환경변수

**exe는 `.env` 파일을 읽지 않는다.** 설정은 `기사작성기-server.bat`의 `set` 줄 또는 시스템/서비스
환경변수로만 한다. (`npm run server`가 쓰는 `--env-file-if-exists=.env`는 dev 전용 Node CLI
플래그다 — 배포 폴더에 `.env`를 만들어도 아무 효과가 없다.)

| 이름 | 기본값 | 설명 | 주의 |
|------|--------|------|------|
| `PORT` | `3001` | 서버 포트 | bat이 `set PORT=3001`로 명시한다 |
| `HOST` | `127.0.0.1` | listen 바인드 주소 | loopback 밖(`0.0.0.0` 등)으로 열면 `COLLECTION_TOKEN` 미설정 시 수집 인제스트 HTTP 라우트가 503 `collection-disabled`로 비활성된다(FTP 스풀 수집은 영향 없음) |
| `DATA_DIR` | **exe 옆 `data`** | news.db·uploads의 루트 | 기본값이 exe 위치 기준이라 보통 설정 불필요. 데이터만 다른 드라이브에 둘 때만 지정 |
| `SPA_DIR` | **exe 옆 `web`** | 웹 화면 정적 루트 | 빈 값(`set SPA_DIR=`)이면 화면 서빙 강제 비활성(API만) |
| `COLLECTION_TOKEN` | (없음) | 수집 인제스트 HTTP 인증 토큰 | LAN 개방(`HOST` 설정) 시 사실상 필수 |
| `RCV_SPOOL_DIR` | (없음) | 수집 FTP 스풀 폴더 | **미설정 = FTP 수집 비활성** |
| `DIST_SPOOL_DIR` | (없음) | 배부 스풀 루트 | **미설정 = 배부 비활성**(파일을 쓰지 않는다) |
| `ALLOWED_ORIGINS` | (빈 목록) | 허용 출처(콤마 구분) | 이 배포(동일 출처 서빙)에서는 **빈 목록이 정상**이다. 별도 출처로 화면을 띄울 때만 설정 |
| `YOUTUBE_API_KEY` | (없음) | 영상 검색 키 | 없으면 검색이 빈 결과 |
| `GOOGLE_API_KEY` / `GOOGLE_CSE_ID` | (없음) | 이미지 검색 키 | 없으면 검색이 빈 결과 |

### 설정하면 안 되는 것

- **`NODE_ENV=production` 금지.** 세션 쿠키가 `Secure`+`SameSite=None`이 되어 평문 HTTP(LAN)
  접속에서 브라우저가 쿠키를 저장·전송하지 않는다 → **로그인 화면은 뜨는데 인증만 조용히
  실패한다**(원인 추적이 매우 어렵다). TLS 종단(HTTPS 프록시)이 앞에 있을 때만 켠다.
- **`FORCE_HTTPS=true` 금지.** 같은 이유다 — TLS 종단이 외부 프록시에 있을 때만 켠다.

## 6. 배부 운영 (선택)

- `DIST_SPOOL_DIR`를 설정하면 배부가 활성화된다(예: bat에서 `set DIST_SPOOL_DIR=%~dp0data\dist-spool`).
- 앱은 스풀 폴더에 기사 파일(JSON)을 **쓸 뿐, 네트워크로 보내지 않는다** — 실제 발송은 외부
  전송기가 스풀을 읽어 수행한다(별도 운영 요소).
- 엠바고 시점 배부는 **앱 내 타이머가 없다.** 외부 cron(Windows 작업 스케줄러 등)이
  `POST /api/distribution/tick`을 Z(관리자) 세션으로 주기 호출해야 한다.
- 세션은 1시간 슬라이딩 만료라 **호출 때마다 로그인 → 세션 획득 → tick** 순서로 실행한다.
  PowerShell 예시(작업 스케줄러에 등록):

```powershell
# tick-distribution.ps1 — Z 계정 자격증명을 이 파일에 평문으로 두지 마라.
# (Windows 자격 증명 관리자, 환경변수, 또는 보호된 비밀 저장소에서 읽어와라.)
$base = "http://127.0.0.1:3001"
$cred = @{ userId = "<Z-계정ID>"; password = "<비밀번호-외부에서-주입>" } | ConvertTo-Json
$login = Invoke-RestMethod -Method Post -Uri "$base/api/login" -ContentType "application/json" -Body $cred
Invoke-RestMethod -Method Post -Uri "$base/api/distribution/tick" -Headers @{ "x-session-id" = $login.sessionId }
```

## 7. 수집 운영 (선택)

- FTP 수집: `RCV_SPOOL_DIR`를 설정하면 그 폴더를 감시한다 — 외부 FTP 서버(FTPd)가 그 폴더에
  파일을 떨어뜨리는 구성이다. 미설정이면 FTP 수집이 비활성이다.
- HTTP 수집(`/api/collection/receive`·`/pull`): LAN 개방(`HOST` 설정) 시 `COLLECTION_TOKEN`이
  없으면 503으로 비활성된다(위 환경변수 표 참조).

## 8. 백업 / 복구

- **백업 = 서버 중지 후 `data\` 폴더 복사.** (`news.db` + `-wal`/`-journal` 동반 파일 + `uploads\`
  전부가 그 안에 있다.)
- 복구 = 백업해 둔 `data\`를 제자리에 되돌려 놓고 서버를 켠다.
- **DB 파일을 지우지 마라.** 이 앱은 어떤 데이터도 삭제하지 않는 원칙(비파괴) 위에 있다 —
  운영 중 문제가 생기면 삭제가 아니라 백업 복구로 대응한다.
- `data\`의 `instance-lock.db`는 0바이트 잠금 표식이라 백업·복구에 영향이 없다(서버 중지
  상태에서는 지워도 무방하고, 다시 켜면 새로 만들어진다).

## 9. 업그레이드

1. 새 배포 폴더를 원하는 위치에 푼다.
2. 서버를 멈추고, 이전 폴더의 `data\`를 새 폴더로 옮긴다(또는 `DATA_DIR`로 이전 위치를 지정한다).
3. 새 폴더의 bat으로 기동한다. 스키마 마이그레이션은 부팅 시 자동·멱등이며 기존 데이터를 보존한다.
4. 이전 폴더는 확인이 끝날 때까지 보존한다(롤백 경로).

## 10. Windows 서비스로 등록 (선택)

- **NSSM 권장**: `nssm install 기사작성기-server "<폴더>\기사작성기-server.exe"` 후
  NSSM 편집 화면(또는 `nssm set <서비스명> AppEnvironmentExtra PORT=3001 ...`)에서 환경변수를
  설정한다(서비스는 bat을 거치지 않으므로 환경변수를 서비스 설정에 직접 넣어야 한다).
- `sc.exe create`는 권장하지 않는다 — 콘솔 앱을 그대로 서비스로 올리면 서비스 제어 요청에
  응답하지 않아 시작 실패/강제 종료로 이어진다.
- 자동 등록 스크립트는 동봉하지 않는다(관리자 권한·환경 의존이라 조용히 실패하면 원인 추적이 어렵다).
- 서비스가 기동 직후 종료·재시작을 반복(플래핑)하면 같은 `data\` 폴더로 다른 인스턴스(콘솔 실행
  포함)가 떠 있는지 먼저 확인한다 — 그때의 안내 메시지는 **콘솔 전용**이라 서비스로 돌릴 때는
  NSSM의 stdout/stderr 리다이렉트를 설정해 파일에서 확인해야 한다(아래 11절 "이미 실행 중" 항목).

## 11. 문제 해결

- **SmartScreen/백신 경고**: 이 exe는 코드 서명이 되어 있지 않다 — "추가 정보 → 실행"으로
  진행하거나 조직 정책에 따라 신뢰 등록한다. (코드 서명 도입은 별도 과제다.)
- **설치 경로 주의**: `C:\Program Files` 같은 보호 경로에 두지 마라 — exe 옆 `data\`에 DB·업로드
  파일을 써야 하는데 관리자 권한 없이는 쓰기가 막혀 **EPERM/EACCES로 기동이 실패한다.**
  `D:\기사작성기-server`처럼 쓰기 가능한 경로를 쓰거나, 부득이하면 `DATA_DIR`를 쓰기 가능한
  폴더로 지정하라.
- **포트 충돌(EADDRINUSE)**: 다른 프로세스가 포트를 쓰고 있다 — bat의 `set PORT=`를 바꾼다.
- **콘솔에 "이미 실행 중" 메시지가 뜨고 즉시 종료됨**: 같은 `data\` 폴더로 두 번째 서버를 실행한
  것이다(데이터 폴더당 서버 인스턴스는 1개다 — 두 개를 띄우면 로그인 세션·실시간 갱신이 서버마다
  갈라지고 배부가 중복될 수 있어 막는다). 조치: 기존 서버(콘솔 창)를 종료한 뒤 다시 시작하거나,
  두 대 운영이 필요하면 `DATA_DIR`를 서로 다른 폴더로 지정한다. 기존 서버의 콘솔 창을 찾지
  못하면 **작업 관리자에서 `기사작성기-server.exe`를 이름 기준으로 종료**하고, 그래도 정리되지
  않으면 서버 PC를 재부팅한 뒤 한 번만 실행한다. 강제 종료·정전 뒤에도 잠금은 남지 않는다 —
  그냥 다시 켜면 된다.
- **로그인이 안 됨**: ① `NODE_ENV`가 설정돼 있지 않은지 확인(위 5절 — 평문 HTTP에서 로그인이
  조용히 실패한다) ② 브라우저 쿠키 차단 여부 ③ `data\news.db`에 사용자가 있는지(위 4절).
- **수집 HTTP가 503 `collection-disabled`**: LAN 개방 상태에서 `COLLECTION_TOKEN`이 없다 — 토큰을
  설정한다(부트 경고는 Z 관리자 로그 화면에만 남는다 — 콘솔에는 나오지 않는다).
- **배부 파일이 안 생김**: `DIST_SPOOL_DIR` 미설정(= 배부 비활성)이다.
- **화면(SPA)이 안 뜸**: exe 옆 `web\` 폴더가 있는지, `SPA_DIR`를 빈 값으로 강제 비활성하지
  않았는지 확인한다(API `/api/health`가 200이면 서버 자체는 정상).
- **LAN에서 접속 불가**: `HOST` 설정 여부 + Windows 방화벽 인바운드 허용(해당 포트)을 확인한다.

## 12. 로그

- 로그는 **파일로 저장되지 않는다.** 메모리 링 버퍼에만 있고 Z(관리자) 화면에서 조회한다
  — 서버 재시작 시 유실된다.
- 부팅 진단(바인드 주소·SPA 경로·수집 경고)도 같은 메모리 로그로만 남는다 — **콘솔 창에는
  아무것도 출력되지 않는 것이 정상**이고, 콘솔에 글자가 보이면 그것은 크래시(EPERM·EADDRINUSE
  등)다. 문제 원인 추적 순서: ① 콘솔 크래시 출력 → ② Z 관리자 로그 화면(로그인 가능할 때).
