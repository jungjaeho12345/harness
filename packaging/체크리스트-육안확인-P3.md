# 기사작성기 — P3 서버 전환(Spring) 육안 확인 체크리스트

**대상이 다르다.** `packaging/체크리스트-육안확인.md`(phase 60~65)는 **Electron 클라이언트 배포**를 본다.
이 문서는 **서버를 Node(SQLite)에서 Spring(MySQL)으로 바꾼 직후**를 본다 — 클라이언트 exe·화면(`web/`) 산출물은
**한 줄도 바뀌지 않았다**(phase 76 · ADR-017). 그래서 여기 있는 항목은 전부 「같은 화면이 **다른 서버** 위에서
그대로 도는가」를 사람이 확인하는 것들이다.

**여기에는 자동 판정이 되는 항목을 넣지 않았다.** 자동으로 판정되는 축은 아래 §B 의 커맨드가 소유한다 —
자동 커맨드가 있는 항목을 육안으로 내리면 그 축은 **다음 회차부터 아무도 안 본다**.

절차를 따라 하고 결과 칸에 `정상` / `제약 있음` / `미확인` 중 하나를 적어 담당자에게 회신해 달라.
**하나라도 `제약 있음`이면 롤백 판단자(§0-9묶음)를 부른다** — 혼자 판단하지 않는다.

전제: 런북 `docs/cutover-p3.md` **§9-5(Spring 기동)** 까지 끝났고 `§9-6` 의 자동 검증이 통과한 상태.
접속 주소는 **컷오버 전과 같다**(같은 host:port — 클라 config·북마크 무변경).

## C. 왜 A 의 항목들은 자동화할 수 없는가

- **1·2·3·4**: 사람의 물리 입력(키보드·IME·프린터 드라이버·OS 클립보드)과 OS 창을 넘나든다. 합성 입력은 IME·메뉴바 경로를 재현하지 못하고,
  비표시 창은 포커스가 없어 클립보드 왕복이 거부된다(기존 체크리스트 3·5·6번과 같은 사유).
- **5**: 파일 서빙 자체는 자동 판정되지만(`UploadsStaticWireTest` · spa-parity `/uploads` 200) **화면에 픽셀이 그려졌는가**는 단언 대상이 아니다.
- **6**: 자동 판정은 **Electron 1창**까지다. 브라우저 2창의 동시 갱신 체감은 판정 수단이 없다.
- **7**: 계약 하네스는 `news_ct`(ALL 권한)의 임시 DB 에서 돌아 **권한 축을 구조적으로 못 본다** — `--db mysql --parity` 가 green 인 채로 이 라우트만 500 이다(§7-6 T5).
  `SHOW GRANTS` 는 「붙어 있는가」만 보고, **화면 → 라우트 → DB 까지의 실사용**은 사람만 본다.
- **8**: 로그 화면은 Z 전용 SSE 이고, 「줄이 흐르는 체감」은 자동 단언 대상이 아니다. **Node 5줄 ↔ Spring 1줄**이라는 사실을 사람이 알고 봐야 오독하지 않는다.
- **9**: 브라우저 개발자 콘솔의 CSP 위반은 지금 어떤 하네스도 수집하지 않는다(spa-parity 는 **헤더 바이트**만 본다 — 위반은 페이지가 실제로 실행될 때 난다).
- **10**: 자동 판정이 **가능한** 항목이다(한 줄 스크립트로 충분하다 — 런북 §9-8). 그런데도 여기 두는 이유는 둘이다: 컷오버 당일 사람이 한 번 더 보아야 하고, **며칠에 걸쳐 반복**해야 하기 때문이다.
- **11**: 포트·프로세스 목록은 앱 밖이고, `/api/health` 는 두 인스턴스를 구분하지 못한다(둘 다 `{ok:true}` · 인스턴스 식별자 없음).
- **12**: 롤백 자체가 사람의 결정이다.

**이상 발견 시 DB 를 직접 고치지 말고 담당자에게 보고해 달라.**
(전환 직후의 이상은 대부분 **설정값**(`DATA_DIR`·`SPA_DIR`·`DIST_SPOOL_DIR`·포트)이고, 데이터를 손대면 롤백 자산이 무효가 된다.)
