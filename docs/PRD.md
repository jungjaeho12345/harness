# PRD: 기사 작성기 (Article Production System)

## 목표
기자·데스크·관리자가 기사를 **작성 → 검수 → 송고**하는 사내 보도 제작 도구. 전체는 제작(기사작성기)·수집(자동기사)·배부 3개 시스템으로 구성되며, 현재 구현 범위는 **3개 시스템 전부**다(배부는 2026-07-26 스코프 확장 — ADR-008 아키텍처를 따른다).

## 사용자
- **R (기자/리포터)**: 기사 작성·송고·보류·KILL.
- **D (데스크)**: 기사 검수, 고침/포털고침, 송고(→DPS)·보류·삭제 승인, 편집 잠금 강제 해제.
- **Z (관리자)**: 데스크 권한에 더해 사용자(USER) 관리와 수신 설정(rcvMgmt) 관리.

## 핵심 기능
1. **로그인 / 세션**: DB USER 테이블 대조 로그인, 1시간 슬라이딩 세션, F5 복원, 로그인 레이트리밋(15분/10회), bcrypt 해시, `active='N'` 비활성 차단.
2. **기사 작성(writer.do)**: 60:40 에디터/메타데이터 레이아웃, 4개 메타 탭(공통정보/이미지/영상/글기사), 블록 기반 에디터(제목·부제·본문 색상, 임베드, Alt+Y "(끝)" 마커), 다중 작성 탭(sessionStorage 보존), 편집 잠금(lockYN).
3. **기사 조회(list.do)**: SSE 실시간 목록, 4개 메뉴(데스크 미송고/부서별 작성/부서별 송고/개인별 수정), 우클릭 컨텍스트 메뉴, 10개 페이징, 컬럼 표시/간격 설정, 상태 배지, 상세보기 새 창.
4. **기사 생애주기**: 권한 × 상태 × 액션 전이 규칙(RDS / DPS / RRH / RRK / DDH / DDK), 송고 시 "(끝)" 마커 검증, 신규 최초 송고는 RDS 유지.
5. **미디어 임베딩**: 서버 프록시로 YouTube(영상)·Google 이미지(이미지) 검색(API 키는 서버 환경변수), 내부 글기사 검색, 외부 실패 시 빈 결과.
6. **수집 / 자동기사(rcv)**: FTP(이벤트)·API 수신 → 파싱(제목·본문) → Article/Contents 등록(속성 '자동기사'), 미등록 ID 차단, 수신 설정 CRUD(rcvMgmt.do, Z 전용).
7. **사용자 관리**: USER 입력/수정/조회(Z 전용), 비밀번호는 응답에 절대 미포함.

## MVP 제외 사항
- ~~배부 시스템~~ → 2026-07-26 스코프 확장으로 착수(ADR-008). 배부 UI 보강·실패 재전송은 후속(MVP-4).
- 우클릭 메뉴의 이력보기/송고이력보기/번역/매핑/후속·계속기사작성/재송 (메뉴 표시만, 동작 안 함). (삭제요청은 DPS 기사 삭제 승인 → DPD 전이로 동작한다 — D/Z 전용.)
- HTTPS 강제, HttpOnly/Secure/SameSite 쿠키 세션, SSE 인증 강화, 계정 잠금 등 추가 보안 하드닝(후속 과제).
- 본문 평문(content) 컬럼 — 본문은 markupVersion 블록 JSON에만 저장(평문 컬럼 미사용).
- 보조 인덱스, FK 제약 (정합성은 애플리케이션이 유지), Dept 테이블 (부서는 컬럼으로 관리).
