# Step 1: deserialize-fallback

본문 역직렬화가 **블록 스키마가 아닌 JSON**을 만나면 본문을 통째로 빈 배열로 만들어, 사용자가 저장하는 순간 원본이 영구 소실되는 하자(감사 항목 B, med — 이 phase의 데이터 유실 축)를 읽기 쪽 복원력으로 막는다.

## 읽어야 할 파일

- `CLAUDE.md` — "DB에 있는 내용은 절대 삭제하지 않는다" 규칙과 TDD 규율
- `phases/66-minor-backlog/index.json` — scope (B), decisions **(3)(4)(5)(20)(22)**, excluded (e)
- `docs/SCHEMA.md` — Article.markupVersion 저장 계약(본문은 서버에 불투명 문자열로 저장된다는 사실)
- `web/src/view/editorContent.js` 전체(87줄) — 특히 `normalizeBlocks`(36~48행: 텍스트/임베드 **외 전부 드롭**), `deserialize`(55~72행: 66행 배열 분기 · 67행 blocks 객체 분기 · 71행 평문 폴백)
- `web/src/view/editorContent.test.js` 전체(116줄) — 기존 계약 케이스(30~47행의 평문 역호환·빈값 계약이 이 step의 불변 조건이다)
- `web/src/view/articleDetail.js` 60~70행 — 상세보기가 같은 역직렬화 결과를 렌더한다는 소비처 근거(수정하지 않는다)
- `web/src/view/ListPage.jsx` 130~145행 — 본문 복사 경로의 같은 소비(수정하지 않는다)
- `src/services/articleService.js` 1~30행 — 서버가 본문을 필드 화이트리스트로 그대로 저장한다는 사실(쓰기 경로를 **고치지 않는** 근거)

## 배경 (실코드 확인 결과)

- `deserialize`는 문자열을 JSON으로 파싱해 **최상위가 배열이면 즉시** 블록 정규화 결과를 반환한다. 정규화는 `text`/`embed` 타입이 아닌 원소를 전부 버린다 → 예를 들어 문자열 배열이나 다른 스키마의 객체 배열이 저장돼 있으면 결과가 **빈 배열**이다.
- 그 결과: 에디터 본문이 빈 화면, 상세보기 공백, 본문 복사 결과가 빈 문자열. 사용자가 그 상태에서 저장하면 정상 블록 문서로 재직렬화되어 **원본 텍스트가 영구 소실**된다.
- 반대로 **blocks 배열이 없는 객체 문자열**은 파싱에 성공해도 두 분기 어디에도 걸리지 않아 평문 폴백으로 떨어지고 원문이 텍스트 블록으로 보존된다. **이 계약이 이 step이 확장할 본보기**다.
- 쓰기 경로에는 본문 스키마 검증이 없다(서버는 문자열로 저장). 이 step은 **읽기 쪽만** 고친다.

## 작업

TDD 순서를 지킨다: **먼저 red 테스트 → 그다음 구현**.

### A. red 테스트 추가 (`web/src/view/editorContent.test.js`)

`deserialize` 관련 케이스가 있는 describe에 아래를 추가한다(기존 케이스는 수정 금지).

1. **문자열 배열 JSON** — 여러 줄이 담긴 문자열 배열 형태의 JSON 문자열을 넘긴다. 기대: 결과가 **비어 있지 않고**, 원문 텍스트가 텍스트 블록으로 보존된다(모든 블록의 텍스트를 이으면 입력 원문과 같다). 수정 전에 실패해야 한다.
2. **다른 스키마의 객체 배열 JSON** — 블록 타입이 아닌 객체가 담긴 배열 JSON 문자열. 기대는 1번과 같다.
3. **blocks 키를 가졌지만 원소가 전부 미지 타입인 객체 JSON** — 배열 분기와 **대칭**으로 원문이 보존된다.
4. **의도적으로 빈 문서는 그대로 빈 본문**(회귀 잠금) — 원소가 없는 배열 JSON과, blocks가 빈 배열인 정규 문서 JSON 두 가지 모두 결과가 빈 배열이다. **폴백이 여기까지 번지면 안 된다.**
5. **부분 드롭은 오늘 동작 유지**(경계 잠금) — 정상 텍스트 블록 1개와 미지 타입 1개가 섞인 배열은 정상 블록만 남는다(폴백하지 않는다).
6. **정합 문서 무회귀**(회귀 잠금) — 정규 문서 JSON·평문 여러 줄·빈 문자열/`null`/`undefined`가 오늘과 똑같이 동작한다(기존 케이스와 중복돼도 이 step의 의도를 드러내는 값이 있다면 남기고, 완전 중복이면 추가하지 마라).

### B. 구현 (`web/src/view/editorContent.js`)

- 문자열 입력의 JSON 분기에서, **파싱된 블록 원본 배열의 길이가 0이 아닌데 정규화 결과가 비어 있으면** 반환하지 말고 평문 폴백 경로로 낙하시킨다(그 경로가 원문 텍스트를 줄 단위 텍스트 블록으로 보존한다).
- 이 규칙을 **배열 최상위 분기와 blocks 객체 분기 양쪽에 대칭으로** 적용한다.
- **원본 배열 자체가 비어 있으면 오늘처럼 빈 본문을 반환한다**(정상적으로 저장된 빈 문서를 JSON 문자열로 되살리지 않는다).
- **부분 드롭은 손대지 않는다**(정상 블록이 하나라도 남으면 그대로 반환).
- 문자열이 아닌 입력(블록 배열·문서 객체를 직접 넘기는 경로)은 **한 줄도 바꾸지 마라** — 돌아갈 원문 텍스트가 없다.
- 함수 주석에 "정규화가 전량 드롭한 JSON은 원문 보존을 위해 평문으로 취급한다(유실 방지)"는 계약과, 빈 문서·부분 드롭 예외를 명시한다.

## 검증 절차

1. **red 먼저**: A의 1~3번을 추가하고 구현 전에 대상 파일 테스트를 돌려 실패를 확인한다(실패 개수·메시지 요지를 요약에 기록). 그 뒤 B를 구현한다.
2. AC를 전부 실행한다. 역직렬화는 소비처가 많다(본문 편집·상세보기·인쇄·복사·찾기·정렬) — 위 목록의 파일 테스트가 전부 green인지 개별로 확인하고 요약에 적어라. 전체 스위트 1건 실패는 **재실행 2회**로 판정한다(알려진 flake).
3. **변이 검증 3종**(각각 red 확인 후 원복):
   - (a) 폴백 조건에서 "원본 배열이 비어 있지 않을 때"라는 단서를 빼기(= 항상 폴백) → A-4(빈 문서 계약)가 red.
   - (b) 폴백을 부분 드롭까지 확대 → A-5(경계 잠금)가 red.
   - (c) 폴백 자체를 제거(원복 상태) → A-1~3이 red.
4. **왕복 실증**(테스트가 아니라 관측 — 요약에 기록): 손상 문서 문자열을 역직렬화 → 직렬화 하면, 결과 문자열 안에 **원문 텍스트가 그대로 남아 있는지** 확인하라(수정 전에는 본문이 사라진다). 리포 `news.db`나 실행 중인 서버에 **절대 접속하지 마라** — 순수 함수 두 개를 메모리에서 왕복시키는 것으로 충분하다.
5. `git status --porcelain` 증분이 소유 파일(`web/src/view/editorContent.js` · `web/src/view/editorContent.test.js` · `phases/66-minor-backlog/index.json`)뿐인지 시작 시점 스냅샷 대비로 확인한다.
6. 아키텍처 체크: `server/**`·`src/**`·`client/**`·`web/src/model/**` 무수정 · 새 파일 0 · DB 접속 0 · 의존성 불변.
7. `phases/66-minor-backlog/index.json`의 step1 status·summary를 갱신한다.

## 금지사항

- 정상 문서(정규 블록 문서·평문·빈값)의 동작을 조금이라도 바꾸지 마라. 이유: 이 역직렬화는 모든 본문 읽기의 단일 진입점이라, 한 글자 어긋나면 전 기사에 즉시 영향이 간다.
- 원소가 없는 배열/빈 blocks 문서를 폴백시키지 마라. 이유: 정상적으로 저장된 빈 문서가 JSON 문자열 한 줄로 되살아나 **새 데이터 오손**이 된다(고치려던 것과 같은 종류의 사고다).
- 부분 드롭(정상 블록 + 미지 블록 혼재)까지 폴백을 넓히지 마라. 이유: 멀쩡히 읽히는 문서 전체를 JSON 덤프 한 줄로 바꿔 손해가 더 크다 — 관측 가능한 유실이 아닌 케이스다.
- `normalizeBlocks`의 화이트리스트를 넓혀 미지 타입을 통과시키지 마라. 이유: 그 화이트리스트는 렌더·직렬화·XSS 방어(임베드 검증)가 딛고 선 계약이며, 모르는 타입을 본문에 들이는 순간 렌더 계층이 무방비가 된다.
- 서버·백엔드(`src/services/**`)에 본문 스키마 검증을 추가하지 마라. 이유: 계약 변경이고 기존 데이터를 거부할 위험이 있다 — 이 phase 범위 밖이다(decisions (5)).
- `docs/news.md`를 열어 수정하지 마라(읽기도 불필요). 이유: 사용자 소유 미커밋 수정이 있는 무접촉 파일이다.
