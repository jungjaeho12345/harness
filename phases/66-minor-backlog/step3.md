# Step 3: dialog-exclusivity

비모달 다이얼로그들이 각자 독립 표시 상태를 갖고 열기 경로가 자기 것만 켜서, **화면 중앙 같은 자리에 무제한으로 겹쳐 쌓이는** 하자(감사 항목 D, low)를 닫기 헬퍼 하나로 정리한다.

## 배경 (실코드 확인 결과)

- 중앙 고정 공통 클래스를 쓰는 다이얼로그가 **15종**이다: 약물입력 · URL임베드 · 표편집 · 메타선택 · 문서열기 · 파일정보 · 사진발행 · 메모장 · UI언어 · 도움말 · 에디터정보 · 약어관리 · 간체번체 · 이력비교 · 맞춤법결과. 여기에 **환경설정 모달**(화면 전체를 덮는 배경을 가진 유일한 모달)이 더해져 그룹은 **16종**이다.
- 이들에는 배경 가림막이 없어 메뉴바가 계속 클릭 가능하다 → 열린 채로 다른 항목을 고르면 같은 자리에 새 다이얼로그가 겹쳐 뜨고, 아래 것은 완전히 가려진 채 살아 있다.
- **찾기/바꾸기는 그룹이 아니다** — 우상단 고정 도구 패널이고 스타일시트 주석이 그 예외를 명시한다(본문을 보며 쓰는 용도). 우클릭 컨텍스트 메뉴도 그룹이 아니다.
- 탭 전환 조정 블록은 지금 **7종만** 닫는다(문서-로컬 좌표를 든 것들). 나머지는 탭이 바뀌어도 열린 채 이월된다.
- 전수 스캔 결과, "다이얼로그가 탭 전환을 견뎌야 한다"고 단언하는 기존 테스트는 **0건**이다. 두 개 이상의 다이얼로그를 동시에 열어 둔 채 단언하는 기존 테스트도 없다(같은 테스트에 여러 다이얼로그 이름이 나오는 경우는 전부 메뉴 활성 확인이나 순차 열기/닫기다).

## 작업

TDD 순서를 지킨다: **먼저 red 테스트 → 그다음 구현**.

### A. red 테스트 추가 (`web/src/view/WriterPage.test.jsx`)

새 describe 하나에 대표 6케이스를 담는다(기존 케이스 수정 금지).

1. **불리언 → 불리언**: 파일 정보를 연 뒤 도움말 열기를 연다. 기대: 도움말만 남고 파일 정보는 문서에서 사라진다.
2. **페이로드형 다이얼로그**: 표 삽입 다이얼로그를 연 뒤 메모장을 연다. 기대: 표 다이얼로그가 사라진다. **본문(저장 호출의 본문 인자)이 변하지 않았음도 함께 단언**하라(닫기가 편집으로 새지 않는다는 증거).
3. **모달 방향**: 메모장을 연 뒤 환경설정을 연다. 기대: 메모장이 사라진다.
4. **찾기 패널 제외 계약(양방향)**: 찾기/바꾸기를 연 뒤 파일 정보를 열어도 찾기 패널은 남아 있고, 반대로 파일 정보가 열린 상태에서 찾기를 열어도 파일 정보는 닫히지 않는다.
5. **탭 전환 델타**: 메모장(지금은 탭 전환에서 안 닫히는 쪽)을 연 뒤 다른 탭으로 전환한다. 기대: 닫힌다.
6. **메타 팝업 필드 전환 회귀 방지**: 공통정보의 한 필드 팝업을 연 채 다른 필드 트리거를 누른다. 기대: 새 필드 기준으로 열리고 이전 필드 선택이 새 필드에 기록되지 않는다(phase 32가 확정한 remount 계약이 이 변경으로 깨지지 않았다는 증거).

1~3·5는 수정 전에 **반드시 실패**한다. 4·6은 수정 전에도 green이어야 하며 과잉 닫힘·계약 파손을 잡는 잠금이다.

### B. 구현 (`web/src/view/WriterPage.jsx`)

1. **닫기 헬퍼 1개**를 만든다 — 그룹 16종의 표시 상태를 전부 닫힘 값으로 되돌린다.
   - 선언 위치는 **그룹 state 선언 뒤 · 탭 전환 조정 블록 앞**이다. 이 파일에는 렌더-중 조정 블록이 아래 선언을 참조해 죽는 문제 때문에 선언을 위로 올린 전례가 주석과 함께 남아 있다(같은 함정을 반복하지 마라).
   - 헬퍼는 **표시 상태만** 닫는다. 맞춤법 결과 목록·본문 하이라이트·이력비교 목록/선택/요청 미러 같은 부속 데이터는 건드리지 않는다.
   - 선언부에 계약 주석을 남긴다: 그룹의 정의(중앙 한 자리를 공유하는 다이얼로그 + 전체 화면 모달), 찾기 패널과 컨텍스트 메뉴가 제외인 이유, **새 중앙 다이얼로그를 추가하면 여기에 등록해야 한다**는 규칙, 그리고 **환경설정 모달을 헬퍼로 닫는 것은 `onPrefsClose(applied)` 경로를 우회하므로 '취소'와 동일하다** — 적용 전 강제 닫힘이면 그때까지의 편집분은 저장되지 않는다(저장은 '적용'에서만 일어난다). 다만 모달이 화면 전체를 덮어 메뉴·탭 클릭이 막히고 에디터 단축키도 포커스가 없어, 실제 도달 경로는 사실상 없다.
2. **탭 전환 조정 블록**에서 현재 나열된 다이얼로그 닫기 호출들을 헬퍼 호출 한 줄로 대체한다. 그 블록의 나머지(마지막 캐럿·상태표시줄 캐럿·맞춤법 결과/하이라이트·이력비교 부속 state·요청 미러 정리)와 각 줄의 이유 주석은 **그대로 둔다**.
3. **모든 열기 경로**에서 여는 상태 변경 **바로 앞**에 헬퍼를 호출한다. 실측된 열기 경로:
   - 메뉴 핸들러의 열기 분기 전부(환경설정 · 도움말 · 에디터 정보 · URL 임베드 5종 · 파일 정보 · 메모장 · 약어관리 · 사진발행 · UI 언어 · 표 삽입 · 약물입력 · 간체번체)
   - 비동기 열기 2종 — **각 함수가 실제로 여는 state 변경 바로 앞**이며, 그 위치는 두 함수가 서로 다르다(코드를 직접 확인하고 옮겨 적지 마라):
     - 문서열기 피커(886~892행)는 **먼저 열고 목록을 뒤에 채운다** — `setShowOpenDialog(true)`가 함수 첫 줄이고 `await`는 그 뒤다. 따라서 닫기는 **그 첫 줄 바로 앞(= await 전)** 이다. `await` 뒤에 두면 헬퍼가 방금 켠 플래그를 도로 꺼서 피커가 아예 열리지 않고 기존 문서열기 케이스(테스트 파일 2955~3030행 부근 6건)가 통째로 red가 된다. **그 파일의 함수 주석은 stale이니 주석이 아니라 코드 순서를 믿어라.**
     - 이력비교(680~695행)는 **조회 결과를 받은 뒤 연다** — 닫기는 `setShowHistoryCompare(true)` 바로 앞(= await 뒤)이다.
   - 맞춤법 검사 실행 경로(결과 다이얼로그를 여는 지점)
   - 우클릭 메뉴의 약물입력 · 단축키(Alt+O)의 약물입력
   - 본문 표 더블클릭(표 편집 열기)
   - 공통정보가 메타 팝업 열기를 prop으로 직접 받는 지점 — 상태 설정 함수를 그대로 넘기지 말고 **닫기 후 여는 얇은 래퍼**로 감싼다
4. **열리지 않는 경로에서는 부르지 마라** — 매핑 가드·대상 없음 등으로 return하는 분기, 그리고 닫기 전용 분기(맞춤법 해제 등)는 그대로다.
5. 순서 계약: 닫기는 **여는 state 변경 바로 앞·같은 동기 구간**이다(같은 렌더 배치로 합쳐져 중간 상태가 렌더되지 않는다). "await 앞이냐 뒤냐"가 아니라 **"여는 줄 바로 앞이냐"**가 기준이다 — 비동기 함수마다 여는 줄의 위치가 다르다(위 3의 두 사례). 메타 팝업은 이 배치 안에서 이전 필드 → 새 필드로 값이 바뀌므로 remount 계약이 그대로 유지된다.

## 검증 절차

1. **먼저 파악**: 구현 전에 `npx vitest run --root web src/view/WriterPage.test.jsx`를 한 번 돌려 기준선 통과 수를 기록한다(이 파일이 이 phase에서 가장 큰 회귀 표면이다).
2. **red 먼저**: A의 1~3·5를 추가하고 구현 전에 실패를 확인한다(실패 개수·메시지 요지를 요약에 기록). 그 뒤 B를 구현한다.
3. AC를 전부 실행한다. **기존 케이스가 하나라도 깨지면, 테스트를 고치지 말고 먼저 원인을 규명하라**: (i) 닫기를 열리지 않는 경로에서 불렀는지 (ii) 그룹에 넣으면 안 되는 것(찾기 패널)을 넣었는지 (iii) 부속 데이터를 헬퍼가 지웠는지 (iv) **닫기를 여는 지점 뒤에 둬서 방금 켠 플래그를 도로 껐는지**(문서열기 피커가 대표 사례 — 이 증상은 "다이얼로그가 아예 안 열린다"로 나타난다) — 넷 중 하나가 대부분이다. 어느 것도 아니고 "두 다이얼로그가 동시에 떠 있어야 한다"는 **의도된 계약**이 드러났다면, 그 항목만 그룹에서 빼고 **근거를 요약과 `phases/66-minor-backlog/index.json`에 기록**하라(테스트를 약화시키지 마라).
4. 전체 스위트 1건 실패는 **재실행 2회**로 판정한다(알려진 비고정 flake — 회귀로 단정 금지).
5. **변이 검증 3종**(각각 red 확인 후 원복):
   - (a) 헬퍼 호출을 열기 경로 한 곳(파일 정보)에서 제거 → A-1이 red.
   - (b) 찾기 패널을 그룹에 넣기 → A-4가 red(과잉 닫힘 검출 증거).
   - (c) 탭 전환 블록의 헬퍼 호출을 제거 → A-5와 기존 탭 전환 닫힘 케이스들이 동시에 red(단일 출처가 실제로 소비된다는 증거).
   - (d) 문서열기 피커의 닫기 호출을 여는 줄 **뒤**로 옮기기 → 기존 문서열기 케이스들이 red(순서 계약이 테스트로 실제 보호된다는 증거. 이 변이는 반드시 원복하라).
6. `git status --porcelain` 증분이 소유 파일(`web/src/view/WriterPage.jsx` · `web/src/view/WriterPage.test.jsx` · `phases/66-minor-backlog/index.json`)뿐인지 시작 시점 스냅샷 대비로 확인한다.
7. 아키텍처 체크: `web/src/styles/**`·다이얼로그 컴포넌트 파일들·`Editor.jsx` 무수정 · `server/**`·`src/**`·`client/**` 무수정 · 새 파일 0 · DB 접속 0 · Model 계약 호출 변화 0.

## 금지사항

- 표시 상태 16개를 하나의 활성 다이얼로그 state로 통합하지 마라. 이유: 렌더 16곳·열기 18곳·닫기 20곳을 전부 재작성해야 하고 메타 팝업 remount·표 페이로드·이력비교 부속 state 설계까지 다시 세워야 한다 — low 항목의 값어치를 넘는 회귀 표면이다(decisions (9)로 기각됨).
- 찾기/바꾸기 패널을 그룹에 넣지 마라. 이유: 스타일시트가 명시한 별도 슬롯 계약(우상단 고정 도구 패널)이고 중앙 다이얼로그와 겹치지 않는다 — 닫으면 "찾아 놓고 다른 도구를 쓰는" 흐름이 깨진다.
- 헬퍼가 맞춤법 결과·본문 하이라이트·이력비교 목록/선택 같은 **부속 데이터**를 비우게 하지 마라. 이유: 다른 다이얼로그를 여는 것과 탭이 바뀌는 것은 다른 사건이며, 본문 하이라이트가 무관한 조작으로 사라지는 새 동작이 생긴다.
- 매핑 가드·대상 없음 등으로 **열리지 않는 경로**에서 헬퍼를 부르지 마라. 이유: 막힌 클릭이 남의 다이얼로그를 닫는 것은 고치려던 것과 같은 종류의 새 결함이다.
- 닫기 호출을 **여는 state 변경 뒤**에 두지 마라(특히 "await 뒤"라는 규칙으로 일반화하지 마라). 이유: 문서열기 피커는 먼저 열고 목록을 나중에 채우는 구조라, 여는 줄 뒤에 닫기가 오면 피커가 아예 열리지 않고 기존 케이스 6건이 red가 된다 — 기준은 항상 "여는 줄 바로 앞"이다.
- 헬퍼를 그룹 state 선언보다 위나 탭 전환 조정 블록 아래에 선언하지 마라. 이유: 렌더-중 조정 블록이 아래 선언을 참조하면 초기화 전 참조로 즉사한다 — 이 파일에 같은 이유로 선언을 옮긴 전례 주석이 있다.
- 다이얼로그에 배경 가림막·포커스 트랩·z-index 재설계를 도입하지 마라. 이유: 스타일시트와 15개 컴포넌트를 동시에 바꾸는 별개 규모의 UX 작업이다(excluded (f)).
- 소스 텍스트를 정규식으로 세어 그룹 목록 드리프트를 잠그는 테스트를 만들지 마라. 이유: 주석 한 줄에도 무너지는 잠금이고(phase 65에서 실증) web 쪽에는 그런 스캐너 관행이 없다 — 계약은 주석 + 행위 테스트로 남긴다.
- 기존 다이얼로그 계약 테스트를 고쳐서 green을 만들지 마라. 이유: 그 케이스들이 phase 29~32가 실측으로 고친 문서-로컬 좌표 이월 결함을 막고 있다.
